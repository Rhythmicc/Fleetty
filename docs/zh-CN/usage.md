# 使用指南

## 页面

默认界面有四个页面：Overview、Compute、Network 和 Storage。按 `1` 到 `4`，或用 `Tab` 和 `Shift+Tab` 切换。左右方向键同样切换页面；在存储地图里，它们用来进出目录。

Overview 把主机与运行时长、CPU、内存和磁盘健康度、GPU 负载、60 秒网络历史、应用流量、Slurm 节点队列，以及一段进程摘要放在同一屏。Compute 在硬件和队列之后，把剩下的每一行都给进程。Network 显示实时速率、累计总量、60 秒峰值、应用流量，以及各接口的实时和累计计数。

Fleetty 只画这台机器能够提供的数据。没有 GPU 或没有 Slurm 时，对应区域会去掉，周围面板补上空位。方向键、回车和鼠标可以选择进程并打开详情。`/` 过滤进程。`t` 切换主题。`q` 退出。

在 Network 或 Storage 上按 `/` 会先切到 Compute，再打开过滤。在自定义页面上，如果进程面板被隐藏，它也会先把面板展开。

## 常用按键

| 按键 | 功能 |
| --- | --- |
| `1`–`3` | Overview、Compute、Network |
| `4` | 本地 Storage Map |
| `Tab` / `Shift+Tab` | 下一页 / 上一页 |
| `↑` / `↓`、单击 | 选择进程 |
| `Enter` | 只读进程详情 |
| `/` / `c` | 过滤 / 清除过滤 |
| `o` / `O`、点击表头 | 下一个排序字段 / 反转顺序 |
| `PageUp` / `PageDown`、滚轮 | 滚动当前组件 |
| `Home` / `End` | 当前组件顶部 / 底部 |
| `l` | 布局编辑器 |
| `m` | 管理模式 |
| `t` | 为当前会话选择主题 |
| `r` / `q` | 刷新 / 退出 |

主题、页面、过滤和排序都属于当前会话。远程只读详情会遮盖常见的密码、令牌和类似参数。完整详情和任何写操作都需要 [管理模式](security.md)。

在存储地图的重复文件视图里，`c` 用来选择保留哪一份副本，不会清除进程过滤。

## CPU 与历史图

CPU 组件有三种尺寸。SMALL 是整机使用率、负载和历史。MEDIUM 在同一面板里加上逐核负载。LARGE 再加大占用进程。Compute（`2`）默认打开逐核形态（`CPU · PER CORE`），不再另设一张 CPU CORES 卡片。自定义布局按组件尺寸选择形态。

Linux 和 macOS 都按内核的逻辑 CPU 编号显示，每核实时使用率为 0 到 100%，并带负载条。超线程按独立核心计数，不是物理拓扑。完整列表用 `PgUp` 和 `PgDn` 滚动，不会被截断。第一次采样、刚上线的核心或计数器重置会显示 `--`，直到下一次有效采样。没有逐核数据时，面板会直接说明。总览保留整机平均使用率。使用率取相邻两次 CPU 时间的差值。idle 和 iowait 不算忙碌。1、5、15 分钟的 load average 仍是独立的整机指标。

JSON 快照的 `cpu_core_usage` 包含 CPU 编号、`percent` 和 `available`。Prometheus 导出 `fleetty_cpu_core_percent{node="…",cpu="cpu0"}`。Hub 和节点都需要能识别这些字段的版本。

逻辑 CPU 超过 32 个时，Compute 使用紧凑纵向柱图。32 个及以下保留逐核横条。每核一根柱，按 CPU 编号固定排列，不按负载重排。柱宽跟随终端。高度和颜色都表示 0–100%。贴底的 `▁` 是零负载，`?` 表示尚未采样。历史图移到右侧窄栏，避免中等核数的机器被挤在左边。柱图最多两排。窗口很窄或核心非常多时，随选中的核心翻页。采样不会被丢掉。点击柱子，或按 `f` 后用方向键、`Home` 和 `End` 移动。图表下方一行显示编号、负载和 GHz。`Esc` 或 `f` 回到进程操作。`v` 在柱图和完整逐核列表之间切换。这个选择只影响当前会话的 Compute 页。采集、JSON、Prometheus 和自定义布局都不变。

所有历史图都是从底部填起的多行柱图。顶部是 `HIST ·` 加上指标和单位，底部是 `old → now`。CPU 固定为 0–100%。网络 RX 和 TX 共用这个窗口的峰值，并标出该峰值。降采样覆盖整个保留窗口。缺失样本是空隙，不是零，也不是浮动圆点。窗口是空的就继续等待。Overview 只保留一张近期 CPU 历史，不会在旁边再放一张 1 小时图。更早的样本仍然保存着。网络、总览、自定义卡片和 NAS 视图使用同一个组件。宽窗口并排，窄窗口堆叠，或者省掉次要历史。它不会退回单行曲线，也不改变即时负载条。Overview 的网络摘要利用图表旁边的空间，最多五行，窄的时候三行，不把面板撑高。内存和根磁盘用短条。多出来的行给进程表。

CPU 面板还会在每轮采样时更新频率。`AVG` 是有频率样本的在线逻辑 CPU 的算术平均。逐核视图在负载旁边打印 GHz，并给出范围；采样不完整时，还会给出有多少核参与了平均。逐核标题把摘要、负载和元信息收成两行，窗口窄时为三行。历史图放在核心旁边。读数来源保存在导出数据里，不放在这个标题上。

Linux 上的值是 `/proc/cpuinfo` 的 `cpu MHz`，也就是内核报告的当前频率。Apple Silicon Mac 不需要 sudo，Fleetty 直接读 IOReport，并用 IORegistry 报告的 DVFS 档位，按每个核心的活跃驻留时间加权。来源是 `IOReport · active residency`。这不是寄存器读数。第一次采样建立基线。完全空闲或计数器重置的核心显示 `--`。Fleetty 不会用最低、标称、最大或请求频率去填空。接口不存在、状态对不上，或者是不提供这些数据的 Intel Mac 或虚拟机时，面板显示 `CLK --`，而不是 0 GHz。IOReport 是私有接口，系统更新可能改变它。Linux 上的精度取决于内核、硬件和虚拟化平台。

JSON 的 `cpu_frequency` 包含均值、最低和最高 MHz、样本数和来源。`cpu_core_usage[].frequency_mhz` 是逐核 MHz。Prometheus 导出 `fleetty_cpu_frequency_mhz` 和 `fleetty_cpu_core_frequency_mhz`，以及最小、最大和已采样核心数。Hub 的详情使用同一份数据，所以节点必须运行会采集它的版本。

Apple Silicon Mac 还会通过 IOKit、且不需要 root，显示 GPU 总负载、渲染器与 Tiler 利用率、核心数，以及已使用和已分配的统一内存。MacBook 的电量、充放电状态、剩余时间和电源来源在顶栏。没有电池的台式 Mac 会省略它们。这个模式不启动后台服务，不打开端口，也不需要 root。

## 进程

点击表头可按 CPU、内存比例、RSS、运行时长、PID、用户或命令排序。再次点击同一表头会翻转方向。`o` 切到下一个字段，`O` 反转当前字段。两者都不需要管理模式。行范围和总数显示在行上和面板角落。过滤后会加上匹配数量。每个连接保留自己的排序，刷新时保留选中的 PID。

CPU、内存和 RSS 随数值升高，从灰到青、绿、黄、红。进程名不随进程状态变色。`100%` CPU 表示一个逻辑核心。内存比例和 RSS 以整机内存为基准着色。PID 前的标记表示运行（`▶`）、休眠（`●`）、等待（`!`）、停止（`■`）、僵尸或已退出（`×`）、空闲（`○`）。表格里有图例。

## 网络

在 Linux 上，Network 页和大尺寸网络组件列出 IPv4 和 IPv6 的 TCP 与 UDP socket：PID、名称、用户和实时 DOWN/UP。宽度足够时再加上协议、状态以及本地和远端地址。每条 TCP 连接的速率是 Linux `INET_DIAG` / `TCP_INFO` 累计字节计数的差值，每秒刷新。有流量的连接排在前面。同一进程的多条连接分开计数。socket cookie 避免端口复用造出虚假速率。第一次采样显示 `sample…`。计数器重置后重新开始。这个速率是 TCP 载荷，不含协议头，也不是网卡线速。UP 使用已发送字节，其中可能包含重传。UDP、监听 socket、`TIME_WAIT`，以及内核不提供计数的 socket 显示 `--`，而不是假的零。精确的 UDP 字节数需要 eBPF 或抓包，当前没有启用这个采集器。

数据来自当前网络命名空间。普通用户可能看不到其他用户的 socket 属于哪个进程，这时 PID 为 `--`，并提示权限。用户名优先用内核给出的 socket UID，名字解析不了就显示数字 UID。否则使用 Fleetty 已经知道的进程用户。macOS 仍用 `nettop` 提供进程级速率和累计流量。

`fleetty snapshot --processes` 导出同样的连接列表、用户、累计字节、速率，以及 `traffic_available` / `rate_available`，因此未采样和真实的零可以区分开。

Linux 连接列表按实时 `DOWN + UP` 降序，不按单一方向，也不按累计总量。速率相同则保持稳定顺序。每个方向按自己的绝对速率着色：不可用或低于 1 KiB/s 为灰色。从 1 KiB/s 起使用方向色，下行青色，上行紫色。从 100 KiB/s 起为绿色，从 1 MiB/s 起为黄色，从 10 MiB/s 起为橙色。表格图例说明了排序和颜色。颜色表示大小，不表示链路饱和或故障，因为连接本身不知道链路容量。

## 本地存储地图

Storage 页把目录画成面积图。面积是实际分配的磁盘空间。为了避免大量小文件变成无法辨认的碎点，条目按大小分页。一页最多 16 个可以点击的真实条目，终端很小时更少，最少 4 个。`PgUp`、`PgDn` 或面积图上方的翻页可以继续看更小的文件。

扫描当前目录的直接子项时，只有一个子项就用 1 个 worker；否则在 2 到 8 个之间，并跟随 `GOMAXPROCS`。扫描还在进行时，大小、文件数和色块就会更新。已经出现的目录可以直接点击。Fleetty 会取消当前工作并进入该目录，而不是把无关扫描做完。方向键和回车一样。`Backspace`、左方向键或 `h` 回到上级。右方向键打开当前选择。`Home` 回到扫描根。

本会话会把访问过的目录放在有界缓存里。返回时，完整且新鲜的图会立刻恢复。过期或未完成的结果先显示，再在后台重新扫描。`r` 强制重扫当前目录。在重复文件视图里，`r` 改为重扫重复文件。

选中条目后，`d` 永久删除，`z` 先写成 `.7z` 再删除原文件。两者各自打开确认，并要求输入 `DELETE` 或 `ARCHIVE`。压缩需要 `PATH` 里有 `7z`、`7zz` 或 `7za`。Fleetty 在同一文件系统的临时文件里创建压缩包，用 7z 校验，再发布，且不覆盖已有文件。只有这些都成功后才删除原文件。压缩失败时原文件不动。如果压缩包已经发布、随后的删除失败，界面会同时给出压缩包路径和仍然还在的原文件。删除一旦开始就不能中断。压缩可以按 `Esc`，直到它停在安全的位置。扫描根、符号链接、挂载点，以及包含其他挂载点的目录不能删除。

`u` 扫描当前目录里的重复文件。Fleetty 先按大小分组，再用最多 8 个 worker 计算 SHA-256。默认只考虑至少 1 MiB 的普通文件。已有硬链接不重复计入。符号链接、网络挂载和虚拟文件系统会跳过。分组按可回收空间排序，并给出保留路径和待替换路径。`c` 轮换这一组要保留的文件。`g` 为当前组写去重脚本。`G` 为每一个已验证的组写一份。再按一次 `u` 离开重复文件视图。

脚本保存在用户配置目录的 `fleetty/dedupe-plans` 下，权限 `0700`。Linux 上该目录是 `~/.config`（或 `$XDG_CONFIG_HOME`）。macOS 上是 `~/Library/Application Support`。脚本不会自动执行。运行前先看它要保留的路径。执行时每个文件都会再查一次：SHA-256、身份、属主、权限模式，以及扩展属性或 ACL。Fleetty 随后在副本自己的目录里原子替换，只删除已验证的副本，并留下指向保留文件的相对符号链接。检查、建链接或发布失败时，会尝试恢复原副本。之后这些路径依赖被保留的文件。移动或删除它会使符号链接失效，所以批量脚本要先读再跑。

普通用户的扫描和文件操作限制在该用户的 home 内，也限制在该用户已有的权限内。`sudo fleetty top` 或以 root 运行时扫描 `/`，但仍然拒绝删除 `/` 本身。扫描不跟随符号链接，并跳过 NFS、SMB、SSHFS 等网络挂载，以及 `/proc`、`/sys` 等虚拟文件系统。这个页面和文件操作只存在于本地 `fleetty top`。远程会话保持只读，不会获得服务账户改文件的能力。

## 自定义布局

`l` 打开组件编辑器。CPU、内存、磁盘、网络、电池、GPU、节点队列和进程可以重排、隐藏，并设为 `SMALL`、`MEDIUM` 或 `LARGE`。大尺寸组件会增加指标和表格行，不只是把图拉大。在 macOS 上，大尺寸网络组件用 `nettop` 按应用和进程显示实时与累计流量。编辑布局不需要管理模式。

大写 `K` 和 `J` 移动选中的组件。小写 `k`、`j` 或方向键只移动光标。`-` 和 `+` 改变尺寸。空格隐藏或显示组件。鼠标可以操作同样的控件。离开编辑器后进入自定义页面。随时按 `1` 到 `4` 回到内置页面。`s` 为本地用户保存布局。远程会话没有可写的位置，编辑器会说明这一点。默认文件是用户配置目录下 `fleetty/` 里的 `layout.json`。`--layout PATH` 或 `FLEETTY_LAYOUT_FILE` 可以选择其他文件。

NAS profile 目前还不能打开这个编辑器。按 `l` 会提示自定义 NAS 布局尚不可用。
